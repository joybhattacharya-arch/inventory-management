Request Data Flow
1
User changes a filter
FilterBar.vue — four dropdowns: Time Period, Warehouse, Category, Order Status
selectedWarehouse.value = "Tokyo"
2
useFilters composable updates
Singleton reactive state shared across all views; watcher in each view fires
watch(() => getCurrentFilters(), () => loadData())
3
api.js builds HTTP request
Non-'all' filter values appended as URLSearchParams; 'all' = no param sent
GET /api/orders?warehouse=Tokyo&category=Sensors&month=2025-01
4
FastAPI route handler receives query params
Optional typed params; unset params = None = skip that filter
def get_orders(warehouse=None, category=None, status=None, month=None)
5
apply_filters() & filter_by_month() run
Warehouse: exact match — Category/Status: case-insensitive — Month: direct match or quarter expansion (Q1–Q4)
filtered = [o for o in orders if o["warehouse"] == warehouse]
6
Pydantic validates & serialises response
response_model enforces shape; FastAPI returns JSON with HTTP 200
response_model=List[Order]
7
Vue reactivity updates the UI
Reactive ref updated; computed properties recalculate; template re-renders automatically
orders.value = response.data   // triggers template re-render

Key Design Patterns
Singleton Filter State
useFilters() creates reactive refs once at module scope. All views share the same filter state without prop drilling.

Gateway pattern: value 'all' means no filter — the API receives no param for that dimension.
refs + computed Reactivity
Raw API data stored in ref([]). Derived values (chart data, totals, filtered lists) live in computed() — cached until dependencies change, never mutated directly.
In-Memory Filtering
All JSON data loaded into Python lists at server startup via mock_data.py. Filtering is pure list comprehension — fast, stateless, no DB needed.

Caveat: writes (tasks, POs) are lost on restart.
Pydantic Contract
Every endpoint declares a response_model. Pydantic validates shape on the way out and generates the /docs Swagger UI automatically. Update models when JSON structure changes.
